# ADR-008: 복합 질문의 독립 source 검색 병렬 실행

- 상태: 채택
- 날짜: 2026-10-20

## 배경

복합 질문은 개인 기록 검색과 Tavily 웹 검색을 모두 수행한 뒤 답변·검증 단계로 이동한다. 두 source 입력은 서로 독립이지만 기존 그래프에서는 순차 처리했다.

## 검토한 대안

1. 현재 순차 실행 유지
2. `memory_web` 경로에서 두 작업을 bounded thread pool로 동시에 실행
3. 모든 질문 경로를 async로 다시 작성

## 결정

2번을 채택한다. `memory_web`에서만 memory와 web node 함수를 공유 executor에 제출하고 두 결과를 합쳐 기존 answer 노드로 전달한다. executor는 앱 전체에서 최대 8 worker로 제한한다. 검색 클라이언트가 없는 경우에는 빠른 실패 안내를 병렬화하지 않고 순차 fallback을 유지한다.

## 근거

각 독립 작업에 고정 80 ms 대기를 둔 30회 합성 실험에서 p50 지연은 166.60 ms에서 84.60 ms로 49.2% 감소했다. 두 작업 결과는 모두 유지됐고, LangGraph 통합 테스트에서도 barrier로 실제 동시 실행을 검증했다. [F8.4 보고서](../experiments/F8_4_parallel_sources.md)에 조건과 제한을 기록했다.

## 결과와 제약

추가 LLM 호출·토큰 없이 복합 질문의 대기 시간을 줄일 수 있다. 고정 지연 실험은 실제 OpenAI/Tavily 응답시간을 측정하지 않았으므로 제품 전체 지연 개선폭은 미측정이다. executor 포화와 실제 장애 조합은 부하 평가에서 추가 확인해야 한다.
