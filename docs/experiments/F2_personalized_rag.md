# F2 개인 학습 RAG — 실험 기록

## 실행 조건

- 실행일: 2026-10-20 (KST)
- 기준선: `c7469ff` (F1.2 코어 모듈화)
- 후보: SQLite 기반 의미·단어 혼합 검색 및 Agent 출처 연결
- 임베딩 모델: `text-embedding-3-small`
- 검색 평가 자료: 합성 학습 기록 14개, 질의 20개, Recall@3 / MRR 측정
- 답변 비교 사례: `RAG-SEM-01`, 표현을 바꿔 ADC 학습 기록을 묻는 합성 질문
- 실행 명령:
  - `./pharma/bin/python -m unittest discover -s backend/tests -v`
  - `./pharma/bin/python eval/run_rag_experiment.py`
  - `./pharma/bin/python eval/compare_answers.py --case-id RAG-SEM-01 --baseline-ref HEAD`
- 격리: 답변 비교와 검색 측정은 `eval/`의 합성 fixture만 사용했다. 운영 SQLite, 개인 기록, Tavily에는 접근하지 않았다. API가 반환한 사용량·비용 정보는 제공되지 않았다.

## 검색 결과

| 방식 | Recall@3 | MRR | 질의 p50 | 질의 p95 |
|---|---:|---:|---:|---:|
| 2.2 단어 검색 | 0.950 | 0.925 | 0.000초* | 0.000초* |
| 의미·단어 혼합 | 1.000 | 0.942 | 0.160초 | 0.184초 |

인덱스의 최초 생성은 0.67초였다. 이후 내용과 모델이 그대로인 청크의 벡터는 SQLite에서 재사용한다. 검색 임베딩 요청은 매 질문마다 발생한다.

\* 단어 검색 시간은 이 작은 합성 fixture에서 측정 분해능보다 짧아 0.000초로 출력됐다. 의미 검색에 약 160 ms의 p50 추가 지연이 관찰됐다. 최초 임베딩 요청 비용과 네트워크 조건은 별도이며 이번 결과는 대규모 사용량의 성능 예측이 아니다.

## 답변 비교

| 항목 | 기준선 `c7469ff` | F2 후보 |
|---|---|---|
| 라우트 | `memory` | `memory` |
| 응답 시간 | 2.64초 | 3.02초 |
| 답변 핵심 | ADC가 항체에 세포독성 약물을 연결해 표적에 전달 | 같은 ADC 설명, 과거 기록 내용과 일치 |
| 출처 | 없음 | ADC 학습 메모, 바이오시밀러, CAR-T |

후보는 표현이 다른 질문에서 ADC 학습 메모를 찾아 답변했다. 출처 3건 중 바이오시밀러와 CAR-T는 관련성이 낮아 top-3를 그대로 표시할 때 출처가 과하게 붙는 한계가 관찰됐다. 다음 품질 개선에서 점수 임계값/재순위화 또는 출처 수 조정을 검토한다. 이 1회 생성 응답의 시간 차이는 성능 결론으로 해석하지 않는다.

## 기능 검증

- 격리 임시 SQLite에서 임베딩 색인 생성·재사용·기록 수정 후 재생성 확인
- 의미가 다른 표현으로 ADC 기록 검색, 반환된 출처의 원본 ID 확인
- 지원하지 않는 owner 범위는 빈 결과를 반환하는지 확인
- 임베딩 API 오류를 주입해 기존 단어 검색으로 복구하는지 확인
- 결과: `unittest` 4개 통과
- 결과 JSONL은 로컬 `eval/results/rag_retrieval_latest.jsonl` 및 `eval/results/latest.jsonl`에 저장하고 Git에는 올리지 않았다.

## 해석과 한계

이 fixture에서는 Recall@3과 MRR이 모두 개선됐고, 검색 지연은 증가했다. 합성 데이터 14건·질의 20건은 작은 검증 자료이며 실제 개인 기록의 검색 품질을 대표한다고 볼 수 없다. 임베딩 입력은 OpenAI API로 전송된다. 현재 소유자 범위는 단일 사용자 `local`이므로 다중 사용자 격리는 후속 F7에서 DB 소유권 설계와 함께 검증해야 한다.
