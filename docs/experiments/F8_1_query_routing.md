# F8.1 Query Routing 실험

## 질문

기존 라우터가 최신 정보가 필요 없는 일반 개념 질문을 개인 기록 검색으로 잘못 보내는지 확인하고, 경로 우선순위를 분명히 한 프롬프트가 분류 품질과 지연에 도움이 되는지 비교했다.

## 조건

- 합성 평가 질문 24개: 기사/개념, 개인 기록, 최신 정보, 기록+최신 정보 각 6개
- 같은 모델 `gpt-4o-mini`, temperature 0, 같은 `RouteDecision` 구조화 출력과 입력 데이터
- 기준선: F7.2의 `agent_router` 시스템 프롬프트
- 후보: 경로의 의미와 판정 우선순위를 명시한 집중형 프롬프트
- 각 조건 1회 실행. 실제 사용자 기록이나 기사 데이터를 사용하지 않음
- 재현: `python eval/run_routing_experiment.py`

## 결과

| 측정값 | 기존 프롬프트 | 후보 프롬프트 |
|---|---:|---:|
| 경로 정확도 | 23/24 (95.8%) | 24/24 (100%) |
| p50 라우팅 지연 | 1,152 ms | 1,046 ms |
| 입력+출력 토큰 | 20,765 | 20,859 |
| 출력 토큰 | 1,215 | 1,141 |

기준선은 “CAR-T의 기본 원리를 알려줘”를 `memory`로 분류했다. 후보는 `article`로 분류했다. 같은 소형 평가셋에서 정확도가 4.2%p 높아지고 p50 지연이 약 9.2% 줄었다. 총 토큰은 약 0.5% 증가해 토큰 절감 효과는 확인되지 않았다.

## 결정과 한계

후보 프롬프트를 운영 라우터에 채택했다. 한 건의 합성 오분류를 바로잡았고 별도 LLM 호출을 추가하지 않으면서 p50도 감소했다. 총 토큰은 소폭 증가했으므로 비용 최적화로 해석하지 않는다.

질문은 유형별로 균형을 맞춘 합성 사례 24개뿐이고 각 입력을 한 번씩 실행했다. LLM 결과는 비결정적일 수 있으며 실제 사용자 질의 분포에서의 품질이나 p95 지연은 측정하지 않았다. 평가 원자료는 개인 정보 없이 `eval/results/routing_latest.json`에 생성되며 Git에는 포함하지 않는다.
