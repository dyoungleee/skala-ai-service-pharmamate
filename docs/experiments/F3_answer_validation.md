## 기능 검증

- 지원되는 수치·날짜는 근거에서 통과하는지, 근거에 없는 임상 단계·수치·날짜는 수정 판정을 받는지 확인
- 평가 목적과 실제 결과를 혼동하는 답변은 revise, 결과 미보고를 정확히 말하는 답변은 pass인지 확인
- 첫 검증 실패 뒤 최대 1회만 재작성하는지, 수정 후에도 실패하면 근거 부족 답변을 반환하는지 확인
- Validator 예외 시 답변을 검증 완료로 취급하지 않고 안전한 안내를 반환하는지 확인
- F2 검색 회귀 포함 `unittest` 16개 통과
- 비교 및 판정 상세 JSONL은 로컬 `eval/results/`에 저장하고 Git에 올리지 않았다.

## 해석과 한계

이번 합성 사례에서는 모든 라벨과 일치했지만 13건은 작은 평가셋이다. 수치·날짜의 표기가 달라 실제로 같은 근거인 경우 결정적 규칙이 재작성을 유발할 수 있다. LLM Validator도 주장 누락이나 잘못된 판정을 할 수 있으며, 결과는 제공된 출처의 진실성까지 보장하지 않는다. 실제 사용 전에 도메인 검토를 거친 임상·승인·용량 자료의 평가셋을 늘려야 한다. 추가 LLM 호출은 응답 지연과 비용을 높인다.
