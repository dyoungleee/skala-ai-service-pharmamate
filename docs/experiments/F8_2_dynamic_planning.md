# F8.2 Dynamic Planning 실험

## 질문

현재 라우터가 `memory_web`를 고르면 기존 그래프는 개인 학습 기록과 최신 웹 검색을 순차적으로 실행한다. 이 복합 경로 앞에 별도 LLM Planner를 추가하면 필요한 작업을 더 잘 찾거나 완료율을 높이는지, 추가 호출 비용을 정당화하는지 비교했다.

## 조건

- 합성 복합 질문 12개. 각 질문은 개인 학습 기록 검색과 최신 웹 검색을 모두 요구함
- 같은 모델 `gpt-4o-mini`, temperature 0, 동일한 라우팅 프롬프트
- 기준선: 라우터 한 번 호출, `memory_web` 경로는 memory와 web 작업으로 해석
- 후보: 같은 라우터 다음에 `memory`/`web` 작업을 열거하는 구조화 Planner를 추가
- 작업 완수율은 필요한 두 검색 작업이 모두 정확히 선택됐는지로 판정. 실제 검색과 답변 생성은 실행하지 않음
- 각 조건 1회 실행. 재현: `python eval/run_planning_experiment.py`

## 결과

| 측정값 | 현재 복합 경로 | 라우터 + Planner |
|---|---:|---:|
| 필요한 검색 작업 선택 | 12/12 | 12/12 |
| p50 라우팅·계획 지연 | 1,101 ms | 2,036 ms |
| LLM 호출 | 12 | 24 |
| 입력+출력 토큰 | 10,541 | 15,423 |

후보는 작업 선택 품질을 높이지 못했고 p50 지연은 약 85% 증가했다. 요청당 LLM 호출은 두 배, 합산 토큰은 약 46% 늘었다.

## 결정과 한계

별도 Planner를 운영 그래프에 추가하지 않는다. 현재 `memory_web` 경로는 이 평가셋에서 필요한 두 출처를 모두 선택했다. 독립적인 두 작업의 동시 실행은 F8.4 병렬 처리 실험으로 별도 검토한다.

평가셋은 복합 검색 의도가 명확한 합성 질문 12개뿐이다. Planner의 작업 선택만 검사했으며 실제 retrieval 성공, 근거 정확도, 최종 답변 완수율을 측정하지 않았다. 실행 결과 원자료는 Git 제외 경로 `eval/results/planning_latest.json`에 있다.
