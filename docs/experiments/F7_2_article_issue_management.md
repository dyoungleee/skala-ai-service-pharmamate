# F7.2 읽은 기사 중복 판정과 산업 이슈 연결

## 목표

현재 세션 안에서 같은 기사를 중복 저장하지 않고, 서로 다른 기사 중 같은 산업 사건을 다룬 기사를 하나의 이슈로 묶는다. 기사와 이슈 조회도 세션 접근 토큰으로 보호한다.

## 구현

- 같은 세션 안에서 URL 정규화 결과, 공백·대소문자를 정리한 본문 SHA-256, 정규화한 제목을 비교한다. 기존 Notebook용 `read_articles` 저장 로직은 그대로 보존한다.
- `session_articles`, `session_industry_issues` 테이블에 세션 소유 기사와 이슈를 저장한다. 기존 테이블은 수정·삭제하지 않는다.
- 자동 연결은 공통 엔티티, 높은 이슈 문구 토큰 겹침, 사건 유형 및 임상 단계가 맞는 경우에만 수행한다. 임상 단계가 서로 다르면 분리한다.
- 화면에서 기존 이슈를 직접 선택해 자동 판정을 덮어쓸 수 있다. 이슈마다 묶인 기사와 최근 읽은 기사를 화면에 보여준다.
- API는 `/api/sessions/{session_id}/articles/mark-read`, `/articles`, `/industry-issues`를 제공한다. 각 요청은 세션 bearer 토큰을 확인한다.

## 합성 기준 비교

다음 5쌍의 고정 fixture로 이전 URL/제목 중복 판정과 F7.2 동작을 비교했다.

| 케이스 | 2.2 기준선 | F7.2 | 기대 동작 |
|---|---|---|---|
| 같은 URL, 추적 파라미터·www 차이 | 중복 | URL 중복 | 중복 저장 방지 |
| 같은 본문, 다른 URL·제목 | 중복으로 인식 못함 | 본문 해시 중복 | 중복 저장 방지 |
| 같은 HB-101 임상 2상 결과를 다른 문구로 표현 | 이슈 연결 없음 | 자동 연결 | 같은 이슈로 묶음 |
| 같은 후보물질, 다른 임상 단계 | 이슈 연결 없음 | 별도 이슈 | 잘못된 단계 병합 방지 |
| 같은 회사, 다른 후보물질 | 이슈 연결 없음 | 별도 이슈 | 서로 다른 후보물질 분리 |

| 지표 | 2.2 기준선 | F7.2 |
|---|---:|---:|
| 기사 중복 precision | 1.00 | 1.00 |
| 기사 중복 recall | 0.50 (1/2) | 1.00 (2/2) |
| 같은 이슈 연결 precision | 기능 없음 | 1.00 (1/1) |
| 같은 이슈 연결 recall | 0.00 (0/1) | 1.00 (1/1) |
| 서로 다른 이슈 오병합 | 해당 없음 | 0/2 |

실험 스크립트는 실제 데이터베이스 대신 케이스마다 임시 SQLite 파일을 사용한다. 별도로 API 테스트에서 사용자가 기존 이슈를 직접 선택하는 흐름과 세션 간 목록 격리를 확인했다.

## 검증 및 재현

- `PYTHONDONTWRITEBYTECODE=1 ./pharma/bin/python -m unittest discover -s backend/tests -v`: 32개 테스트 통과.
- `npm run build --prefix frontend`: Vue 화면 production build 통과.
- `PYTHONDONTWRITEBYTECODE=1 ./pharma/bin/python eval/run_article_issue_experiment.py`: 비교 수치 출력.

## 한계

5쌍은 동작 규칙을 확인하기 위한 작은 합성 평가셋이며 실제 뉴스 기사 성능을 대표하지 않는다. 자동 연결은 키워드·엔티티 기준이므로 의미가 같은 기사도 표현이 크게 다르면 별도 이슈가 될 수 있다. 화면의 기존 이슈 선택 기능으로 수동 연결할 수 있다. 엔티티 추출이 부정확하면 자동 분류도 영향을 받는다.
