## 생성 방식 비교

먼저 기존 정적 질문과 별도 추천 LLM 호출을 비교했습니다. 정적 방식은 용어 이름만 끼운 고정 질문 3개를 즉시 반환했습니다. 별도 추천 방식은 같은 용어·질문·답변·이력·저장 메모를 바탕으로 학습 목표별 질문을 생성했습니다.

| 방식 | 추천 생성 p50 / p95 | 토큰 합계 | 비용 합계 | 확인 결과 |
|---|---:|---:|---:|---|
| 정적 질문 | 0초에 가까움 | 0 | $0 | 매번 같은 정의·기사 맥락·개념 비교 질문 |
| 동적 별도 호출 | 2.45초 / 3.31초 | 2,856 | $0.000758 | 4건 모두 학습 범주 3개를 생성하고 직전 질문과 중복되지 않음 |

별도 호출 방식은 맥락을 반영했지만 응답에 추가 지연과 비용이 발생했습니다. 이어서 답변까지 포함한 통합 호출과 답변 생성 후 추천 호출을 비교했습니다.

| 생성 전략 | 답변+추천 p50 / p95 | 토큰 합계 | 비용 합계 |
|---|---:|---:|---:|
| 분리: 답변 호출 뒤 추천 호출 | 4.38초 / 4.89초 | 4,903 | $0.001373 |
| 통합: 답변과 추천을 구조화 출력 1회로 생성 | **2.64초 / 3.17초** | **3,073** | **$0.000995** |

동일한 합성 입력 4건의 실험에서 통합 방식은 p50 지연 약 40%, 토큰 약 37%, callback 집계 비용 약 28%를 줄였습니다. 통합 응답은 네 사례 모두 답변과 세 범주의 질문을 반환했습니다. p95는 네 회 중 가장 느린 값이며 일반적인 성능 보장은 아닙니다. 원자료는 로컬 `eval/results/recommendation_strategy_latest.jsonl`에 두고 저장소에는 추가하지 않았습니다.

## 구현 및 확인 사항

- LangGraph 답변 노드가 `answer`와 `recommendations`를 함께 구조화 출력합니다. Validator는 답변 본문을 계속 검사하고, 검증 실패 시 추천을 폐기해 기본 질문으로 대체합니다.
- 추천은 `원리 심화`, `다른 개념과 연결`, `한계·응용 탐구` 각 1개와 학습 목표를 포함합니다. 현재 질문과 최근 대화, 선택 용어의 저장 메모·Q&A를 모델 문맥에 제공합니다.
- Gradio는 세 질문과 학습 목표를 보여주며 버튼 클릭으로 해당 질문을 입력창에 채웁니다. 새 용어 선택이나 대화 초기화 시 기존 추천을 초기화합니다.
- 모델 출력이 중복되거나 구조화 파싱이 실패하면 세 범주 기본 질문으로 이어집니다.
- 추천 내용은 질문 형태라 사실을 보증하지 않습니다. 일부 질문은 일반 배경지식이나 비교 주제를 제안할 수 있으므로 사용자가 후속 답변의 근거를 확인해야 합니다.
- 전체 `unittest` 22개 통과. Gradio 핸들러 흐름은 가짜 Agent 결과로 세 질문 표시·버튼 연결을 확인했습니다. 노트북 변경 셀은 AST 구문 검사를 통과했습니다.

## 재현 방법

정적 질문과 분리 추천 실험:

```bash
python eval/run_recommendation_experiment.py
```

분리 생성과 통합 생성 비교:

```bash
python eval/run_recommendation_strategy_experiment.py
```

직전 기준선과 앱 경로 비교:

```bash
python eval/compare_answers.py --all --baseline-ref dc9acd8
```

각 명령은 합성 사례만 사용하고 실제 LLM API를 호출합니다. 결과 원자료는 `eval/results/`에 로컬 저장되며 Git에 포함되지 않습니다.
